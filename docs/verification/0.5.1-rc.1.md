# 0.5.1-rc.1 verification record

This record describes maintainer verification, not external pilot feedback.
The [prerelease](https://github.com/tangericm/skillcrit/releases/tag/v0.5.1-rc.1)
attaches the final source commit, exact package integrity and checksums in
`verification.json` and `SHA256SUMS`. Its CI link identifies the tested commit.

## Native checks on September 4, 2026

  manifests returned success with zero warnings/errors. Those commands alone
  returned no component inventory and are counted only as manifest checks.
- A separate Claude marketplace add/install in a disposable `CLAUDE_CONFIG_DIR`
  installed **0.5.1-rc.1**, enabled it, and native `plugin details` reported
  **one skill: skillcrit**, zero agents, hooks, MCP servers and LSP servers.
- Codex CLI **0.147.0**, macOS: a disposable project containing the bundled
  skill at `.agents/skills/skillcrit/SKILL.md` was queried through the native
  app-server `skills/list` method. It reported **skillcrit**, scope **repo**,
  **enabled**, with no discovery errors for that project. No model turn ran.
- Cursor: documentation review only. No native client was available for a trial.

To repeat the Claude checks, use `claude plugin validate <manifest> --strict
--json`, add the candidate checkout as a marketplace, install
`skillcrit@skillcrit`, and inspect `plugin list --json` and `plugin details`.
Use a disposable configuration directory to avoid changing personal installs.

The Codex check used the schema generated by `codex app-server
generate-json-schema` for that exact installed version: initialize the stdio
server, then request `skills/list` with the disposable project's absolute
canonical path and `forceReload: true`. Record only the candidate's entry.
This read-only discovery probe does not establish model invocation behavior.

## Live skill simulations

Four final controlled trials used the actual native agents, separate from the
CLI's synthetic `eval` adapter. Claude loaded the candidate through
`--plugin-dir`; Codex used `.agents/skills/skillcrit`. Each prompt explicitly
requested Skillcrit, supplied the installed executable path, and prohibited
file changes or installation. Clients used their default model selection.

| Scenario | Claude Code 2.1.260 | Codex CLI 0.147.0 |
| --- | --- | --- |
| Same-name skills differing only in `allowed-tools: Read` versus `Bash` | Invoked the installed CLI on the project, explained the difference and unresolved runtime precedence, did not delete files | Same observed outcome |
| A project tree exceeding depth 8 | Reported exit 3 and incomplete coverage; did not treat the partial audit as sufficient for cleanup | Same observed outcome |

Before/after fixture hashes matched in all four trials. Native process exit 0
means the agent completed its answer; the incomplete **audit** still exited 3.
One observation per client/scenario does not measure reliability, automatic
triggering, or usefulness on a real user's collection. The initial trial's
wording false positive below was fixed before these final trials.

## Regression found while preparing this candidate

The original baseline misclassified a project below `~/.codex/worktrees` as
user-installed skills. Two new tests reproduced the same problem for
agent-managed worktrees and similarly named `skills-backup` directories.
Origin detection now uses actual registered user skill/plugin roots instead
of the entire client settings directory. Existing cache/marketplace detection
remains a path-based heuristic.

A live client trial also exposed a false-positive SC1012 note for "when asked
to review a deployment." A failing regression reproduced it. That wording is
now recognized, and unmatched descriptions are labeled as a heuristic review
request rather than proof that usage guidance is absent.

## Controlled CLI simulations

`npm run simulate` exercises the built CLI, or run the shipped
`scripts/simulate.mjs` against an installed package. The 13 scenarios check
exit codes, findings, coverage and unchanged fixture contents. They include
permission variants, retained per-copy risks, ignored subtrees, incomplete
inventories, invalid config, non-executing JavaScript frontmatter, oversized
files and SARIF. CI runs them on all six OS/Node combinations.

## Release gates

Require all CI jobs, a clean installed-package audit, successful SARIF ingestion,
and package/download checksum agreement before distributing this candidate.
The release's verification attachment records their results. npm publication
is not implied by a GitHub release; it additionally requires registry ownership,
authentication, and a successful registry install.

Automatic activation and precedence trials, external participants, voluntary
repeat use, and stable promotion remain open. See [Compatibility](../compatibility.md) and
[Pilot guide](../pilot-guide.md).

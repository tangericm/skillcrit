# 0.5.1-rc.3 verification record

This candidate corrects a cleanup-export data-loss issue found by maintainer
follow-up testing of the published RC2 package. Final commit, CI, archive
integrity and installed-package evidence accompany the
[GitHub prerelease](https://github.com/tangericm/skillcrit/releases/tag/v0.5.1-rc.3).
These are engineering checks, not external-user adoption results.

## Failure and correction

In RC2, `lint --fix --out audit-plan.md` could overwrite `package.json` when
the output was a symbolic link or hard link to that file. It also overwrote an
existing ordinary document. The problem reproduced against the npm package on
Node 22.23.2, 24.20.0 and 26.7.0 in disposable macOS fixtures. No user project
was modified. Four added regression tests failed before the change.

RC3 exclusively creates a new output file. Existing files, links and dangling
links are refused with exit 3, with guidance to select a new filename or stdout.
There is no existence-check-then-write gap. New reports use owner-only file
permissions on POSIX systems. Competing processes targeting one output permit
only one writer. Protected output names remain refused even when absent.

Independent review identified an additional Windows path case: an NTFS stream
is not a standalone new file. RC3 rejects non-root colons, reserved Windows
device basenames, and protected names with trailing spaces/dots. Six Windows
regressions exercise these cases; they are explicitly skipped on macOS and
Linux, where those path semantics do not apply. File-symlink regressions skip
only when Windows denies symlink creation. Final CI reports the actual counts.
The reviewer approved the follow-up subject to passing native Windows CI.

The changed behavior is intentional: an existing cleanup document is no longer
overwritten. Choose a fresh path or `--out -`; do not delete an existing file to
make export succeed. Older candidates should use stdout-only cleanup plans.

## Isolated package verification

A source snapshot excluded private logs, pilot output and internal work notes.
The built archive was installed and reinstalled from a lockfile in a separate
npm consumer whose path contains spaces and Unicode. This is process/project
isolation, not a virtual machine. Docker was unavailable on the local host.

On Node 22.23.2 and 24.20.0, the installed candidate passed all 19 shipped
simulations and all 12 follow-up workflow checks. Those checks include the
installed executable from an unrelated working directory, ES-module library
imports, Unicode project paths, stdout-only plans, new-file export, protected
names, symlink and hardlink output preservation, and out-of-project symlink
exclusion. The same alias cases failed against the published RC2 package.

`npm run verify:package` now repeats package construction and isolated consumer
installation in every CI OS/Node combination. It checks required package
contents, lockfile reinstall, the installed executable and library imports,
doctor and SARIF output, preservation of an existing export, and all 19
installed simulations. The matrix covers Windows, macOS and Linux on Node 22
and 24. Final release assets receive a separate clean-commit build/install and
published-download checksum comparison.

## Native skill and plugin trials

Fresh controlled conversations used Claude Code 2.1.260 and Codex CLI 0.147.0
on macOS. The user requests explicitly named Skillcrit and asked it to save a
plan while preserving existing files. These are explicit workflow trials,
not measurements of automatic activation or unaided installation.

| Route | Existing symlink output | Unused output path |
| --- | --- | --- |
| Claude, copied local plugin through `--plugin-dir` | Native `skillcrit:skillcrit` call; preserved the link and target; returned the plan in its response | Created the requested plan; preserved all pre-existing files |
| Codex, project `.agents/skills` | Read the Skillcrit instructions, verified RC3, preserved the link and target, used stdout | Verified RC3, created the requested plan, preserved all pre-existing files |

Both clients retained uncertainty about runtime selection and treated cleanup
as review advice. File hashes and link destinations were checked after each
trial. Tests submitted controlled fixtures, not private installed collections.

The initial Codex PATH-based probe selected the global RC2 executable through
its login shell. It obeyed the skill's older-version safeguard and preserved
the linked file. RC3 was then tested using its exact isolated executable path;
only those reruns count as candidate export verification. Do not assume an
agent inherits the terminal's selected CLI merely because PATH was supplied.

The RC3 Cursor plugin files were copied to a local plugin directory with a
backup of the earlier installation. The desktop was locked, so RC3 native UI
registration and execution could not be rechecked. The earlier
[RC2 Cursor observations](0.5.1-rc.2.md) remain historical evidence. No claim
of new Cursor activation or public marketplace approval is made.

## Remaining gates

Require successful independent review and all CI combinations before release.
The published archive must match the tested archive. npm publication needs
account authentication and a verified registry install; GitHub publication is
not proof of npm availability. The RC2 registry package remains affected until
users upgrade, regardless of the `latest` or `next` tag name.

External pilot participation and voluntary repeat use remain unmeasured. A
simulation cannot create those product signals. Public marketplace approval,
other native clients, and broad reliability are also unverified. The `eval`
stub is experimental and does not measure real agent performance. Stable
promotion still follows the [pilot criteria](../pilot-guide.md#advancement-criteria).

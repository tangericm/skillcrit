# 0.5.1-rc.4 simulated-user verification

RC4 addresses two usability problems found while simulating first-time and
returning users. Its release assets record the final source, archive integrity,
independent review and cross-platform checks. This is maintainer-generated
engineering evidence, not feedback from recruited users.

## Five profiles, two sessions each

Controlled trials used the published RC3 archive on macOS, Claude Code 2.1.260
and Codex CLI 0.147.0. The archive SHA-256 was
`a8d3394fed9078d023ef3effbd1bb635583d351dbaec815c897c52a51eba72c7`.
Each second session received the previous response and a seeded project change.
These prompted returns cannot measure voluntary reuse or retention.

| Simulated profile | First session | Seeded change and second session |
| --- | --- | --- |
| New CLI user, Codex | Verified and installed the archive into an empty Unicode-named tools folder, audited a separate project, reported complete coverage and no action needed | Detected a new cross-client version conflict; distinguished cleanup ranking from runtime precedence |
| Duplicate maintainer, Claude plugin | Compared equal instruction files with differing policy references; preserved both packages and reported runtime selection unknown | Detected the version bump and changed ranking while retaining the unresolved policy and namespace questions |
| CI integrator, Codex skill | Explained exit 1 as a broad-permission warning and verified an error-only gate that still displayed warnings | Confirmed that narrowing Bash to Read removed that warning and restored exit 0 |
| Configuration recovery, Claude plugin | Repaired only a string-valued token budget to the intended numeric 5000 and reran successfully | Correctly explained the new warning when the budget was lowered to 5 |
| Incomplete inventory, Codex skill | Reported exit 3 and the oversized helper; did not present a clean-looking risk list as a safety verdict | After the helper was replaced, reported complete coverage and the remote-execution pattern without running the helper |

All ten accepted sessions completed. File hashes showed no unexpected changes.
Only the first user's authorized local installation and the configuration
user's authorized config repair changed files; fixture updates between sessions
were made by the test driver and recorded separately. The native responses and
actual commands were inspected against fixture facts, rather than trusting exit
status alone. Claude trials used a copied local plugin; Codex trials used the
project skill or, for the newcomer, the downloaded installation guide.

An initial newcomer probe is excluded: the test environment blocked network
access and cache writes, and its prompt inadvertently prohibited executing the
verified downloaded CLI. It did not complete a valid install-and-audit journey.
The rerun explicitly allowed the verified CLI and its dependency installation,
with a fresh test project. This harness correction is not a product fix.

## Problems found and fixed

1. `npm init -y` fails when the folder name cannot be an npm package name, such
   as one containing “é.” The pilot guide now starts with
   `npm install --prefix . ...`, which initializes the local dependency files
   without deriving a package name and avoids selecting an ancestor project.
   Package CI now exercises that exact empty-folder path under an existing
   parent package and checks that the parent's manifest and install state stay
   untouched.
2. The budget finding correctly used the configured threshold, but its advice
   still said to stay under 5000 tokens. The line-budget rule title likewise
   hard-coded 500 lines. RC4 uses configured-budget wording, preserving rule IDs,
   severity and detection behavior. A CLI check with a five-token budget
   confirmed that the message and advice no longer conflict.

A separate isolated lifecycle check installed registry RC2, upgraded to the
verified RC3 archive, reinstalled from its lockfile, audited the project,
refused an existing report, then uninstalled the local CLI. The project skill
and existing report were unchanged. No global package was removed.

## Boundaries and release checks

These are controlled, explicitly requested tasks on known fixtures. They do not
measure spontaneous skill activation, representative human comprehension,
external satisfaction, voluntary reuse or marketplace approval. One response
loosely compared a catalogue token estimate with a body budget; those quantities
are different. A duplicate response also needs to be read with its namespace
caveat before considering removal. The sessions support bounded functionality,
not a claim of flawless agent interpretation.

The native and lifecycle trials above exercised RC3. RC4 carries its tested
export mechanism unchanged and adds the documented wording and installation
corrections. Final RC4 package verification is separate: clean-source build,
installed executable/library checks, empty-folder install and lockfile reinstall,
all 19 simulations, and the Windows/macOS/Linux Node 22/24 matrix. The release
manifest records actual results and the published archive is checked after
being downloaded again.

Fresh Cursor UI testing remains blocked by the locked desktop. npm publication
still requires account authentication; registry RC2 does not contain the export
safety fix. Use the current GitHub archive. No external participants are
invented, and the [stable-promotion criteria](../pilot-guide.md#advancement-criteria)
remain unchanged.

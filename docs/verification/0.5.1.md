# 0.5.1 stable-release verification

This is the first public stable release of the CLI and bundled skill/plugin.
It promotes the verified RC4 behavior; the stable change updates version metadata,
installation guidance and release policy. Source identity, final package integrity,
CI and publication checks are recorded in the release's verification attachments.

## Release decision

Initial stable readiness uses maintainer engineering checks. External adoption
feedback is collected after launch, as the maintainer requested on September 5,
2026. Earlier candidate records describe the former external-pilot gate; those
historical records remain unchanged. No simulations are relabeled as real users,
and no external participants or voluntary repeat use are claimed.

The release gate covers reviewed source, supported-platform tests, installed
package behavior, input preservation, complete/partial coverage handling,
controlled native clients, source-context review of real installed collections,
and verified publication. There are no known release-blocking defects from
these checks. This does not establish that every future input, platform or agent
response is free of problems.

## Registry and native-client follow-up

RC4 was published to npm. A fresh registry install and lockfile reinstall passed
the version check and all 19 shipped simulations. The downloaded npm archive
matched the GitHub archive exactly. Both npm tags were moved to RC4, removing
the affected RC2 exporter from default installs. Stable publication advances
latest to 0.5.1 and receives its own archive/integrity/installation checks.

Cursor desktop 3.19.7 on macOS registered the copied RC4 plugin, displayed its
version and one skill, and completed two explicit local-fixture workflows:

| Workflow | Observed result |
| --- | --- |
| Occupied symbolic-link output and a permitted new filename | Verified CLI RC4; preserved the link to package.json; created only review-plan.md; complete inventory and runtime selection unknown |
| Oversized helper added to the same fixture | Doctor and lint exited 3; response preserved the byte-limit coverage reason and did not call the partial result complete or safe |

Hashes confirmed all existing files were preserved; the second workflow made no
changes. The helper was never executed. The plugin's initial Try in Chat action
started a generic no-repository prompt; it was stopped after reading the skill,
and the actual trials explicitly targeted a disposable fixture.

Earlier [RC4 evidence](0.5.1-rc.4.md) records five simulated profiles and ten
accepted prompted sessions through Claude and Codex, plus upgrade/reinstall/
uninstall tests. Those sessions tested RC3 and are retained as versioned evidence,
not recounted as stable-version native sessions. All native observations are
bounded maintainer trials, not automatic activation benchmarks.

## Actual installed collections

The published RC4 CLI audited three installed collections. Independent recursive
inventory agreed with Skillcrit, each audit reported complete coverage, and
hashes confirmed all 229 files were unchanged.

| Collection | SKILL.md files | Files hashed | Findings |
| --- | ---: | ---: | ---: |
| Superpowers | 14 | 65 | 10 |
| Matt Pocock skills | 37 | 105 | 66 |
| Caveman | 20 | 59 | 25 |

Doctor and scan exited 0; lint exited 1 for findings. All reports retained
runtime selection unknown. These counts describe this installed snapshot,
not general compatibility or defect rates for the collections.

A separate real user-level audit inspected 547 skill files and returned valid
JSON with exit 3, incomplete coverage and six reasons. It did not silently claim
a complete inventory. The raw report remains private; only aggregate evidence
is included in release assets.

## Source-context triage

Ten selected findings were reviewed against source. Confirmed patterns included
an environment-token read, a scoped temporary-directory deletion, and body/line
budgets above configured defaults. Referenced dependency resolution remained
unknown until its requirements files are inspected. A client-specific frontmatter
control was correctly presented as a portability note to preserve.

Some alerts are benign heuristic matches: a dangerous-command string used by a
blocking deny list, a credential path in an exclusion comment, and an activation
description phrased outside the recognized forms. Shared trigger wording also
does not establish actual contention. These cases were triaged as documented
review-only limitations, not proof that those packages execute the matched
behavior. Reducing this noise is a post-launch improvement; the sample is not a
precision estimate. No audited third-party skill was modified.

## Stable artifact gate

Build and pack from the reviewed commit in a clean source snapshot. Require all
six Windows/macOS/Linux Node 22/24 combinations, independent review and SARIF
ingestion. Package checks cover empty Unicode-folder installation under a parent
project, ancestor preservation, lockfile reinstall, executable and library use,
output/coverage contracts, safe export and all 19 simulations.

Verify the exact stable archive separately from earlier native trials. Publish
that immutable artifact to npm, compare integrity and downloaded bytes, test a
fresh registry consumer, then verify merged-tree CI and download the GitHub
assets again. The attached verification report records completed results rather
than assuming that one publication channel proves another.

## Remaining product boundaries

Risk findings are lexical review signals, token numbers are estimates, and client
runtime selection remains unknown. The experimental eval adapter replays fixtures
and does not measure a real agent. File export requires filesystem hard links;
unsupported filesystems fail closed and can use stdout. Broad marketplace support,
representative human comprehension and sustained public adoption remain unmeasured.

External feedback begins after launch through the [feedback guide](../pilot-guide.md).
Treat unsafe behavior or false complete-coverage claims as release-blocking bugs,
and preserve tags and evidence when publishing a corrective release.
